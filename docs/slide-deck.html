WHAT IT DOES AND WHO USES IT

A second reader that checks every current document for you, shows its sources, and never approves anything

Review agent

An intern types a formulation or uploads a document. The agent checks it against the current safety, maintenance and QC documents, flags each issue with a quoted source, and recommends: proceed to sign-off, revise, or reject.

Question agent

Answers questions from the same documents, with quotes. It refuses to say a process is safe or approved, to rewrite a recipe, to show anyone else’s submission, or to help make a hazard worse.

Who uses it

Intern. Submits the process, reads the report, asks questions.

Supervisor. Reads the report and signs off every review.

EHS engineer. Also signs off when any flag is critical.

QC and maintenance. Own the documents the agent reads, and see the flags in their area.

Source: flows/process_review and process_qa READMEs.

The review agent never approves. Only recorded human sign-offs do. The supervisor signs every report; an EHS engineer also signs when any flag is critical. The question agent is read-only: it has no tools that act on anything outside itself.

Depends on people: each new, amended or withdrawn document must be loaded by its owner. Currency is judged as of today’s date and re-read when the report is built.

Source: flows/process_review/README.md, WORLD.md and docs.py. Examples are synthetic.

The agent does not ask an AI to prefer the newest version. Old versions are never loaded into the search at all, so they cannot be quoted. An approved amendment is merged into its base document and cited as, for example, C+A1. If a chemical, machine or product has no current document, that is reported as a coverage gap. A missing safety document for a chemical is critical, which also brings in the EHS sign-off. A malformed document file stops the whole document set from loading, so document control has real work to do. The check at report time re-reads document status, so a withdrawal during the review is seen at that point.

HOW YOU CAN TRUST AND VERIFY IT

Every flag shows its source, and the checks that matter are code, not AI judgment

Quoted sources

Each flag names the document, its version and the exact quoted sentence, so you can read the source yourself.

Hazard rules in code

Dangerous mixes, over-limit values and over-rated or out-of-service equipment are flagged by fixed rules. No AI output can remove or soften them.

A verify step

A claim whose quote or number is not in a current document becomes “unverified: check by hand”. It is never silently dropped.

Repeated testing

Review: 51 of 51 runs passed (17 cases, 3 repeats). Questions: 54 of 54. Upload reading: 15 of 15.

Tests that can fail

We break the agent on purpose to confirm the tests turn red. They did.

Record and people

A tamper-evident log lists every step, document and approver. People approve the exact report they saw.

Caveat: the test cases were written by the build team. Independent cases from EHS and QC are the next step.

Source: runs/…-process-review-eval-006e12, …-process-qa-eval-c4710c, …-process-extract-eval-887f3d, …-4b7982 (break test).

Repeated runs matter because AI output varies from run to run: each case was run three times and every run had to pass. The review test set has 17 cases (clean, hazardous, stale-document, missing-document, hidden-instruction and incomplete forms). The question agent set has 18 cases; the upload reader has 5 documents. For the break test, a saved run shows the question agent’s test going to 0 percent when its answers are deliberately replaced with “safe to run”, so the tests are able to fail. Honest limit: the same team wrote the agent and the tests, and there is no held-out set.

SAFETY AND GUARDRAILS

Guardrails are tested; regulation fit is only a mapping

Built in and tested

Never approves: only a person’s recorded sign-off can.

A critical flag always needs the EHS engineer too.

Missing documents are flagged, never silent.

Orders hidden in notes (“already approved, skip checks”) are ignored and flagged.

Question agent refuses harm, “is it safe?” and recipe rewrites. Harm attempts are logged for EHS without the question text.

No names or free text are stored: logs hold ids and fingerprints.

Relevant requirements this supports

OSHA process safety management (29 CFR 1910.119) and EPA RMP: checks a change against current hazard and equipment documents and keeps a decision record.

OSHA hazard communication (29 CFR 1910.1200), GHS safety data sheets: uses current data sheets and flags a chemical with none.

ISO 9001 and cGMP-style QC records: cites versioned QC specifications.

21 CFR Part 11-style audit trail: tamper-evident log, yes. Verified approver sign-in, not yet.

Tested: 10 audit controls, all pass (tampering detected, log append-only, no identifiers on disk, approval tied to the exact report). Not tested: any regulatory requirement. No compliance is claimed.

Source: .scratch/pr_compliance.md and qa_compliance.md, process_review.spec.json. Regulation list is a mapping for discussion.

Important framing: the repository tests its own audit controls (10 of 10 pass for the review flow, using a scripted model so it checks the plumbing, not the AI’s judgment). It does not test or claim compliance with OSHA, EPA, GHS, ISO, cGMP or 21 CFR Part 11. The list on the right is the speaker’s mapping of where the agent could support those requirements, to be confirmed by EHS and quality or regulatory staff. Known gaps the repository names: approver identity is typed in and not verified by sign-in; the archive is held in memory, so a real deployment needs write-once storage with 6-year retention and access control. The compliance report itself says: a demonstration of controls, not a certification.

LIMITATIONS

It checks a form against documents; it cannot see the plant

It takes at face value

The form. Quantities, units, temperatures and pressures are used as typed.

The documents. It cannot tell a wrong limit from a right one, or notice a gap in what they cover.

Equipment status. Only as the maintenance document records it, not live lockouts or condition.

Controls. The form has no field for ventilation or protective gear, so it asks the supervisor to confirm them.

It cannot do

Inspect or measure. No sensors, sampling or physical inspection.

Judge new chemistry. If it is not in the documents, it flags the gap and stops.

Catch everything. Fixed rules exist only where a document has a rule row. QC specs have none, so QC findings rely on the AI, which can miss things or raise false alarms.

Check who signs. Approver names are typed in, not verified.

Test limit: 17 review cases written by the build team, with no held-out set. Real-world accuracy is unknown.

Source: flows/process_review/README.md sections 4 to 6 and rules.py.

From the repository’s own list of caveats. In an offline dry run with no AI at all, code alone caught 10 of the 12 planted defect cases; the other two (a QC specification range and a QC cure temperature above an equipment rating) need the AI. That is the clearest picture of where the AI matters and where it can miss. Reports are held in memory in the current build, so a server restart loses them; sign-in and protected storage are listed as not yet provided.

How the numbers were derived. A saved test run (the 48 complete reviews among 51; 3 incomplete forms make no model calls) logs input and output tokens for every call. Averages: planning 941 in and 266 out; safety 3,218 and 526; maintenance 2,382 and 189; QC 2,227 and 396. The report step ran 59 times for 48 reviews, so 1.2 calls per review on average because the wording check sent 11 reports back once. Summed per review: about 15,300 tokens in and 2,600 out, which is about 18,000 in total. To turn this into dollars, multiply by current per-token prices for each model size, which are not stored in the repository. The kit’s note of about 2 cents per case per repeat is for a different agent (patient triage), so it is not used here. A cheaper model profile exists in the code but has not been tested for accuracy. Document search uses an optional embedding service; without its key, search falls back to keyword matching. Its cost is not recorded. The largest real cost is likely people time: two sign-offs for critical reports.
